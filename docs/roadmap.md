# 路线图

版本维持 `0.0.1-alpha`。以下是依赖真实证据的工程阶段，不代表已经完成。

| 阶段 | 目标 | 进入条件/验收 |
|---|---|---|
| A. 工作区基线 | 可运行本机 Gateway 模拟器和 Console；稳定公共接口 | 本地自动测试与 CI 通过；原型限制明确 |
| B. 关键技术选型 | 先测现有 TypeScript Gateway 的设备控制链路，再决定是否用 Go/Rust 优化已证实的热点；完成管理编码和 C5 链路小实验 | 在相同工作负载下记录时延、有效吞吐、错误率、主机资源和恢复时间；用可复现数据与兼容性结果形成 ADR，未测项目保持未验证 |
| C. C5 Probe 最小固件 | Wi-Fi 接入、身份、能力和有界会话的 ESP-IDF C/C++ 工程 | 已完成 C5 TLS RPC、租约、GPIO 总线、CMSIS-DAP、签名双槽 OTA、扫描与切频状态机；剩余真实 HE20 链路、目标 SWD、电气与掉电证据 |
| D. 调试互操作 | 通过无线探针连接 OpenOCD 或其他经验证后端 | 主机解析器、TCP 分帧和错误恢复已测；真实探针列举、GDB server 和授权目标硬件证据待完成 |
| E. 首个端到端硬件里程碑 | 电脑经 Wi-Fi/C5 探针对授权 STM32F405 烧录和调试 | 在已确认的板卡和电气条件下完成真实连接、烧录、校验与调试；记录稳定性和链路指标，并验证断连、探针重启及操作中断后的安全恢复 |
| F. P4 / OTA / 外设扩展 | 在前序边界稳定后验证 USB、OTA 和逐项总线能力 | 每个功能有具体硬件、资源测量、安全验证及回退路径 |

## 当前未解决的阻塞

- 本机没有 Go、OpenOCD 或 STM32 硬件工具链；ESP-IDF v6.1.1 已安装并完成 C5 构建。
- 没有确认具体 C5/P4 板卡和电气设计，不能给出引脚、SWD 时钟或 USB High-Speed 声明。
- `gh auth status` 为 401；仓库权限、分支保护、Draft PR 和 CODEOWNERS 责任人均未验证，因而不推送远端。
- 设备配对、远端身份、TLS、升级密钥和 STM32 Bootloader 安全模型仍需决策。

下一项最小工作：提供能协商 Wi-Fi 6 HE20 的接入点，完成 COM8 的发现、TLS、租约、DAP、OTA 恢复和双设备测试；随后再扩展控制台的多设备管理界面。

## 后续 TODO

- **测量与语言选型：** 为 TypeScript Gateway 到 C5/目标板的控制链路建立可重复基线，覆盖命令往返时延（P50/P95）、持续有效吞吐、超时与重试、Gateway/C5 资源占用，以及链路中断后的恢复时间。固定测试配置并记录方法和原始结果；只有测量确认主机端存在瓶颈时，才对对应热点做 Go 或 Rust 小范围对照，按性能、正确性、互操作性和维护成本决定是否迁移。
- **STM32 实机闭环：** 接入确认型号和供电/引脚条件的 STM32 板，完成经验证的 SWD 连接、烧录、读回校验和调试；在断网、C5 重启及传输中断场景验证有界超时、租约清理、续传或安全失败及恢复，并保存可复现记录。
- **恢复与稳定性验收：** 在真实链路上重复执行控制和更新任务，覆盖 Wi-Fi 切换、客户端/Gateway 重连、C5 重启、OTA 中断与回滚；确认不会误报成功、留下长期占用资源的会话，或破坏可启动镜像与目标板状态。
