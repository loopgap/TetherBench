# Probe C5 编程规范

本规范约束 `firmware/probe-c5` 自有源码。`third_party/` 保留上游排版和命名，除非上游补丁明确要求修改。组件按 ESP-IDF 组件构建；`main/` 只装配应用入口，组件之间通过公开头文件和 CMake 依赖通信。

## C 与 C++

- 固件组件使用 C11；`main/` 的入口可使用 C++17，但只承担启动和装配，不在其中实现协议或总线逻辑。
- 缩进使用 4 个空格，文件使用 LF，行宽以 120 列为目标。格式由本目录 `.clang-format` 约束，修改后从 C5 工程目录运行 `clang-format -i`，仅处理 `components/`、`main/` 和 `tests/` 中自有的 C/C++ 文件。
- 对外函数和类型使用 `tb_` 前缀；头文件声明与实现保持一致。可被 C++ 引用的 C 接口使用 `extern "C"`。组件私有状态和仅本文件使用的函数声明为 `static`，状态名应能说明用途。
- 组件对外头文件放在 `components/<component>/include/`，私有实现留在组件目录。每个 `idf_component_register()` 明确列出公开和私有依赖；禁止依赖其他固件工程的私有源码。
- 在最靠近输入边界的位置校验长度、范围、枚举、保留位和状态；解析 wire 数据时逐字段读取/写入，禁止直接映射 C 结构体或依赖编译器填充。响应必须校验序号、操作码、状态和精确长度；未知值按失败处理。
- 仅对相同请求可安全重放的成功结果使用响应缓存；反映可变设备状态的查询（包括目标 OTA 状态、C5 OTA 状态和 Wi-Fi 扫描）必须绕过缓存，避免返回过期状态。
- 缓冲区、队列、任务栈、重试次数和超时必须有明确上限。复用固定容量存储；只有所有权和生命周期清楚时才动态分配。每次资源获取都要在每条失败路径释放，持久化状态必须先于擦除、激活等不可逆步骤提交。
- 可变状态由一个明确的任务或互斥锁拥有；共享状态的锁顺序固定，锁内不等待网络或无上限 I/O。组件 API 明确输入所有权、输出长度以及错误时是否修改输出。错误不得伪装成成功、空结果或已回滚。
- 快速 GPIO 和 SWD 时序留在 C5 本地执行。网络、日志、Flash 与阻塞等待不得进入位时序关键路径；共享外设按租约取得和释放，释放和超时路径要使硬件回到安全状态。
- 头文件只暴露跨组件需要的最小接口；实现细节、临时缓冲和持久化布局留在组件内部。新增依赖前先检查 IDF 或现有组件是否已提供所需能力。
- 主机回归编译自有 C 代码时保留 `-Wall -Wextra -Werror`；不得为消除自有代码告警而关闭告警。确需豁免的上游源文件应把豁免限制在该文件或编译目标。

## Python 工具与测试

- `tools/` 脚本使用 4 空格缩进、标准库优先、明确超时和失败退出码；不打印密钥、令牌或私有配置。测试使用临时目录和替身隔离外设，不写入用户数据或真实设备。
- 新的状态机、解析器、持久化和安全行为应有边界测试，覆盖截断、超长、未知值、重复请求、超时和失败恢复中与该改动相关的情况。主机替身只验证它覆盖的逻辑，不能替代 C5 实机、掉电或无线链路验收。
- 组件变更先运行 `tools/test_core.py`、`python -m unittest discover -s tests -p 'test_*.py' -v` 和 `tools/build.ps1`。使用项目支持的已激活 ESP-IDF 环境；缺少环境时记录未运行的构建，不在仓库内复制 SDK。协议或 Gateway/控制台接口变更还要从仓库根目录运行 `npm run check`；提交前运行 `git diff --check`。
- 在 C5 工程目录中，用以下 PowerShell 命令格式化或检查自有 C/C++ 文件；格式化后再运行检查，不把格式化应用到 `third_party/`：

  ```powershell
  $files = Get-ChildItem components, main, tests -Recurse -File -Include *.c, *.h, *.cpp | ForEach-Object FullName
  clang-format -i --style=file $files
  clang-format --dry-run --Werror --style=file $files
  ```

安全、资源所有权和错误处理优先于缩短代码；不为尚未支持的硬件行为引入虚构引脚、成功状态或模拟器保证。每份验收记录区分主机测试、IDF 构建、仿真和实机证据，并写清未覆盖的故障条件。
