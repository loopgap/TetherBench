# P4-C5 SPI 传输契约

状态：**v1 设计并行实现中；未完成 P4↔C5 实机波形和连续事务验收**。

本契约只描述 `WT9932P4-TINY` 工作 profile 与 `WT9932C5-TINY` 之间的本地 SPI 链路。它不把 COM9/COM10、模拟器或 USB PING 当作 SPI 已通过的证据。引脚来源和排针位置以 [Wireless-Tag Tiny 板级配置](wt-tiny-pin-profile.md) 为准。

## 物理层

P4 是 SPI master，C5 是 SPI slave。两块板分别由 USB 供电，只连接 GND；不得并联两个板的 3.3 V 输出。双方 I/O 必须确认是 3.3 V。

| 信号 | P4 | C5 | 方向 |
|---|---:|---:|---|
| `SCLK` | GPIO16 | GPIO0 | P4 → C5 |
| `MOSI` | GPIO17 | GPIO1 | P4 → C5 |
| `MISO` | GPIO18 | GPIO8 | C5 → P4 |
| `CS_N` | GPIO19 | GPIO9 | P4 → C5 |
| `IRQ` | GPIO20 | GPIO24 | C5 → P4 |
| `RESET_N` | GPIO21 | EN | P4 → C5 |
| `GND` | 左排针第 9 脚 | 任一 GND | — |

首轮时钟固定为 8 MHz，模式 0，MSB first。确认短线、共地、片选和错误率后才允许评估更高频率，设计上限为 20 MHz。P4 的 `RESET_N` 必须开漏输出：拉低复位，释放时高阻；C5 上电和复位期间 P4 的 SCLK、MOSI、CS_N 保持高阻或安全空闲电平，`CS_N` 为高。

## 固定事务

每次片选有效期间传输恰好 1024 字节。短帧必须补零，长帧或非零尾部拒绝。C5 未被选中时 MISO 必须高阻。IRQ 是 C5 的电平通知线，未准备响应时保持低，准备好完整响应帧后拉高；P4 读完响应并释放片选后，C5 清除 IRQ。

1024 字节载荷使用 C5 现有 `TBUP` 帧编码：

| 偏移 | 大小 | 字段 |
|---:|---:|---|
| 0 | 4 | ASCII `TBUP` |
| 4 | 1 | 版本 `1` |
| 5 | 1 | 操作码 `0..TB_TARGET_ABORT` |
| 6 | 1 | 状态码 `0..TB_TARGET_TIMEOUT` |
| 7 | 1 | 保留，必须为 `0` |
| 8 | 4 | 非零序列号，小端 |
| 12 | 2 | 数据长度 `0..997`，小端 |
| 14 | 2 | 保留，必须为 `0` |
| 16 | 0..997 | 数据 |
| 16+length | 4 | CRC-32，覆盖偏移 `0..15+length` |
| 20+length..1023 | 余量 | 必须全为 `0` |

CRC-32 使用现有 `tb_crc32` 实现（初值和多项式保持与 C5 核心一致）。任何 magic、版本、保留位、序列号、长度、CRC 或尾部检查失败都丢弃本次事务并返回有界错误；不得把损坏帧交给 DAP、OTA 或目标总线。

## USB 边界

P4 当前的 USB CDC bridge frame 固定为 32 字节，其中只有 24 字节载荷；它与本契约的 1024 字节 `TBUP` 事务不是同一种帧。当前没有批准的分片、重组、序列号映射或操作码映射，因此 P4 不得把 USB frame 截断后直接当作 `TBUP`，也不得在丢失响应后自动重放调试写入或 OTA 写入。完成这些映射前，P4 只提供本地 `PING` 和 `LINK_OFFLINE` 响应，`tb_bridge_link` 保持显式初始化且 DAP 离线。

后续启用 DAP 或目标 OTA 前，必须先增加独立的、带版本和总长度的 USB 分片契约，明确分片顺序、超时、重复片段处理、整包 CRC、非幂等请求的未知结果恢复，以及 1024 字节 `TBUP` 的完整性检查；该契约通过后才能接入 P4 主循环。

## 状态与恢复

- C5 链路默认关闭。未显式选择 `wt-tiny-p4-c5-spi-v1` 且完成资源冲突检查时，两端不得驱动这些 GPIO。
- 初始化失败、SPI 超时、IRQ 超时、CS 错误或连续两次 CRC 错误后，设备进入 `LINK_OFFLINE`，释放 SPI 资源并把 IRQ 拉低。
- P4 只在检测到 C5 就绪 IRQ 后发起请求；单次事务超时上限为 100 ms，重试最多一次，且仅允许重试幂等的状态/查询操作。
- 非幂等操作（目标 OTA 写入、激活、复位和调试写事务）丢失响应后必须先查询状态，禁止自动重放。
- 恢复顺序为：停止新请求、拉低 `RESET_N` 至少 10 ms、释放为高阻、等待 C5 IRQ 就绪，重新交换能力/状态，再恢复上层租约。恢复失败保持离线，不忙等。
- C5 复位、P4 USB 重连和 Wi-Fi 会话变化都不得清除上层持久化 OTA 状态；SPI 链路只负责有界传输。

## 验收证据

代码自检只能证明帧布局和资源边界；硬件验收至少需要记录：GND 连通、3.3 V 电平、`CS_N` 空闲高、复位释放波形、8 MHz 下连续 1000 个双向事务的 CRC 错误数、掉线恢复时间，以及 P4/P4X 丝印。未完成这些证据前，控制台和文档必须显示“SPI profile 待实机验收”。
